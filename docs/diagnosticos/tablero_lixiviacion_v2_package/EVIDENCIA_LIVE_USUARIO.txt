Regla validada:

    WHEN fecha_registro >= '2026-06-01T21:00:00'
     AND DATEPART(HOUR, fecha_registro) >= 20

            DAY,

5. Ventana hidráulica y asignación de campaña — VALIDADO LIVE
No usar:
ISNULL(fecha_fin_retiro,'2099-12-31')

para asignar señales físicas a campañas.
Eso fue demostrado como incorrecto porque mantenía abiertas campañas históricas y replicaba la misma señal contra hasta cinco campañas.
La campaña se preagrega primero a:
pad_id + campana_id + parcela_id

Fragmento validado:
WITH campana_parcela_base AS
(
    SELECT
        c.pad_id,
        c.campana_id,
        c.numero_campana,
        c.parcela_id,

        MIN(c.fecha_primer_riego)
            AS fecha_primer_riego,

        MAX(c.fecha_ultimo_riego)
            AS fecha_ultimo_riego

    FROM inventar_SpcHidr.campana_parcela_control c

    GROUP BY
        c.pad_id,
        c.campana_id,
        c.numero_campana,
        c.parcela_id
),

campana_parcela_orden AS
(
    SELECT
        c.*,

        LEAD(c.fecha_primer_riego) OVER
        (
            PARTITION BY
                c.pad_id,
                c.parcela_id

            ORDER BY
                c.fecha_primer_riego,
                c.campana_id
        ) AS siguiente_primer_riego

    FROM campana_parcela_base c
),

campana_parcela AS
(
    SELECT
        c.*,

        CASE
            WHEN c.fecha_ultimo_riego IS NULL
                THEN NULL

            WHEN c.siguiente_primer_riego IS NULL
                THEN c.fecha_ultimo_riego

            WHEN c.fecha_ultimo_riego
                 < DATEADD(
                       DAY,
                       -1,
                       c.siguiente_primer_riego
                   )
                THEN c.fecha_ultimo_riego

            ELSE DATEADD(
                    DAY,
                    -1,
                    c.siguiente_primer_riego
                 )

        END AS fecha_limite_hidraulica

    FROM campana_parcela_orden c
)

Asignación:
LEFT JOIN campana_parcela c
    ON  c.pad_id     = f.pad_id
    AND c.parcela_id = f.parcela_id
    AND f.fecha >= c.fecha_primer_riego
    AND f.fecha <= c.fecha_limite_hidraulica

Semántica validada:
límite inferior:
fecha_primer_riego, inclusivo

límite superior:
fecha_ultimo_riego, inclusivo

si la campaña siguiente comienza antes:
día anterior al primer riego de la campaña siguiente

si fecha_ultimo_riego es NULL:
NO abrir hasta 2099;
no se asigna mediante esta regla.

solapamientos:
la ventana se corta antes de la campaña siguiente.

7. Grano físico aprobado como diseño
El hecho hidráulico debe tener grano:
pad_id + parcela_id + fecha

No:
campaña + PAD + parcela + módulo + fecha

porque:
flujo    → parcela/día
drenaje  → parcela/día
refino   → PAD/día

y no existen mediciones hidráulicas por módulo.
Los módulos/CPC deben mantenerse como contexto separado, no copiando flujo/química/transferencia en cada módulo.
La prueba de preagregación campaña/parcela dio:

SULF
2.047 filas
2.047 claves únicas

8. Unidades químicas — VALIDADO LIVE
Para estas fuentes:
cu_pp = g/L

Por tanto:
m³/d × g/L = kg/d

Fórmulas aprobadas para el nuevo contrato:
delta_cu_gl =
    cu_drenaje_gl - cu_refino_gl

transferencia_cu_kg_d =
    flujo_m3_d * delta_cu_gl

transferencia_cu_t_d =
    flujo_m3_d * delta_cu_gl / 1000.0

Ejemplo validado:
672 m³/d
Cu drenaje = 2,03 g/L
Cu refino  = 0,28 g/L
ΔCu        = 1,75 g/L

672 × 1,75 = 1.176 kg/d
            = 1,176 t/d

El tablero legacy actualmente calcula:
flujo_m3_d * delta_cu / 1000

bajo el alias:
transferencia_cu_kg_d

por lo que el valor legacy está realmente en t/d aunque su nombre diga kg/d.
NO cambiar silenciosamente el significado de ese alias dentro del contrato legacy.
En V2 publicar ambos campos con unidad correcta:
transferencia_cu_kg_d
transferencia_cu_t_d

y usar:
cu_drenaje_gl
cu_refino_gl
delta_cu_gl

en vez de _ppm.
